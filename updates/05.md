# Update 05: how to handle tab closes, for the frontend builder

Read `updates/03.md` first. This update changes how you handle the end of a tab. The event format, the endpoint and the billing rule stay the same.

## What to build now

1. **One close per tab.** For each `(accountId, tabId)`, keep one close: the one with the earliest `closedAt`. Ignore any later `tab_close` for the same tab. Still dedupe on `id`.
2. **Show the new reason.** A close can have `reason: "reaped"`. It means the backend found the tab closed without a report. Its `closedAt` is the time the backend noticed, so it can be up to about a minute after the real close. Show these tabs in the usage ledger with the label "closed by backend check".
3. **Handle every reason.** The full list is `closed`, `session_end`, `session_timeout`, `session_closed`, `api_delete_session`, `dead_context`, `reaped`, `server_restart`, a crash or timeout reason, and `unknown`.
4. **Keep the 24-hour cap.** A `tab_open` with no `tab_close` after 24 hours is still closed at the 24-hour mark and flagged for review. It should now be rare.
5. **Don't show browser uptime.** A browser can stay up for a while after its tabs close. That costs us money, not customer minutes, so the billing page should not show it.
