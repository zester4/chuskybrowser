---
title: Payments
description: Let an agent buy on a user's behalf, with the user approving each purchase on their own device.
---

Payments use the user's own card. The agent never sees the card number. Each purchase is approved by the user on their device with a passkey.

## Store a card

```js
import { forUser } from 'chuskybrowser-sdk';

const browser = forUser(userId);
const enrol = await browser.enrolCard();
// Send the link in the response to the user. They enter their card there.
```

Check whether a card is stored:

```js
const cards = await browser.listCards();
```

## Test that your agent can pay

Use the test store to check the whole flow before you use real customers:

- Store: `https://shop.agentcard.sh`. Pick an item and press **Buy now**, then pay with the test card `4242 4242 4242 4242`, any future expiry, and any CVC.
- The agent opens the store, the card request pauses, the user approves the link on their device, and the store confirms the order.

## 1. Arm payment on the checkout page

```js
const armed = await browser.armPayment(tabId, {
  merchant: 'Shop Example',
  amount: 2306,          // $23.06, in the smallest unit of the currency
  currency: 'usd',
  checkoutOrigin: 'https://shop.example.com',
});
// armed.attachmentId: keep it for the next steps
```

| Field | Meaning |
|---|---|
| `merchant` | The store's name. The user sees it on the approval screen. Up to 120 characters. |
| `amount` | The most the user can be charged, in the smallest unit of the currency. `2306` means $23.06. |
| `currency` | A lowercase three-letter code, such as `usd`. |
| `checkoutOrigin` | The address of the checkout page, starting with `https://`. |
| `cardId` | Optional. Which stored card to use. If you leave it out, the first card is used. |

Once armed, the checkout's card request waits for the user's approval instead of going through.

## 2. Send the user the approval link

```js
const status = await browser.paymentStatus(tabId, armed.attachmentId);
```

When the card request is paused, the status includes an `approvalUrl`. Send it to the user unchanged. They open it on their device and approve with their passkey.

The `phase` field tells you where things stand:

- `idle`: payment is armed, nothing is waiting yet.
- `pending`: the card request is paused, waiting for approval.
- `completed`: the purchase went through.

## 3. Record the order

An approved payment is not a finished order. Once the checkout has finished, read the store's confirmation page, then record the order:

```js
await browser.confirmOrder(tabId, armed.attachmentId, { orderId: 'ORD-10482' });
```

If the store shows no order number, pass `{ confirmedWithoutOrderId: true }` instead. The order counts as complete only after this call.

## 4. Cancel payment

```js
await browser.disarmPayment(tabId, armed.attachmentId);
```

Use this if the user decides not to buy, or the task is cancelled.

## Rules for your agent

- Never ask the user for a card number, and never type one into a page.
- Send the approval link to the user exactly as returned. Do not open it yourself.
- Use the amount the user agreed to. Do not raise it.
